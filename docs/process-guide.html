1. Auto API

개요

Auto 모드는 실행·스케줄·상태 조회·메신저 연동을 위한 /api/auto/* REST API를 제공합니다.

목적

  • 번들 즉시 실행 및 취소
  • 서버 스케줄 시작·중지
  • 스케줄 실행 결과 폴링
  • 카카오 OAuth·텔레그램 테스트

주요 구성요소

POST /api/auto/schedule스케줄 start/stopsrc/routes/api/auto/schedule/+server.ts
GET /api/auto/status스케줄 상태src/routes/api/auto/status/+server.ts
/api/auto/kakao/*카카오 OAuth·상태·테스트src/routes/api/auto/kakao/
/api/auto/telegram/*텔레그램 상태·테스트src/routes/api/auto/telegram/

사용 방법

POST /api/auto/execute

title, autoApplyText 필수. URL 1개 이상 또는 enableWebSearch: true 필요.

POST /api/auto/execute/cancel

요청: { "bundleId": "string" } → 응답: { "success": true }

POST /api/auto/schedule

action: start — 번들·스케줄 필드 전달. action: stop — { "action": "stop", "id": "bundleId" }

GET /api/auto/status

활성 스케줄 번들의 isActive, isRunning, lastResult, lastExecutedAt 반환.

2. Auto 실행 파이프라인

개요

Auto 번들 실행은 executeBundle() 함수(src/lib/server/scheduler.ts)에서 오케스트레이션됩니다. Run Now와 스케줄 실행 모두 동일 파이프라인을 사용하며, Run Now만 취소(Abort) 신호를 전달합니다.

목적

  • URL·웹 검색·LLM·메신저 전송을 일관된 순서로 처리
  • Run Now 중단 시 fetch 단계와 전송 전 단계에서 취소 반영
  • OmniRoute 실패 시 로컬 Ollama로 자동 폴백

주요 구성요소

구성요소역할관련 경로
executeBundle실행 파이프라인 본체src/lib/server/scheduler.ts
fetchMultipleUrls참조 URL 일괄 fetchsrc/lib/server/scraper.ts
searchWeb웹 검색src/lib/server/search.ts
callLlmNonStreamingWithLocalFallback비스트리밍 LLM + 로컬 폴백src/lib/server/llm/index.ts
runAbortControllersRun Now 취소용 Mapsrc/lib/server/scheduler.ts

동작 흐름

flowchart TD
    START[executeBundle 시작] --> AB1{signal aborted?}
    AB1 -->|yes| CANCEL[Cancelled 반환]
    AB1 -->|no| URL[fetchMultipleUrls]
    URL --> WS{enableWebSearch?}
    WS -->|yes| SEARCH[searchWeb]
    SEARCH --> TOP3[상위 3 URL fetch]
    WS -->|no| VAL
    TOP3 --> VAL{본문 또는 검색 결과?}
    VAL -->|no| FAIL[오류 반환]
    VAL -->|yes| LLM[callLlmNonStreamingWithLocalFallback]
    LLM --> FB{omniroute 실패?}
    FB -->|yes| LOCAL[로컬 Ollama 폴백]
    FB -->|no| AB2
    LOCAL --> AB2{signal aborted?}
    AB2 -->|yes| CANCEL
    AB2 -->|no| KAKAO{카카오 연결?}
    KAKAO -->|yes| KS[sendMessageChunked]
    KAKAO -->|no| AB3
    KS --> AB3{signal aborted?}
    AB3 -->|yes| CANCEL
    AB3 -->|no| TG{telegramEnabled?}
    TG -->|yes| TS[sendTelegramChunked]
    TG -->|no| OK[success 반환]
    TS --> OK

주요 소스 파일

  • src/lib/server/scheduler.ts — executeBundle, runTask, startSchedule
  • src/lib/server/scraper.ts — URL fetch
  • src/lib/server/search.ts — 웹 검색
  • src/lib/server/kakao.ts — 카카오 OAuth·전송
  • src/lib/server/telegram.ts — 텔레그램 Bot API

참고

LLM 호출에는 abort signal이 전달되지 않습니다. 취소는 fetch 단계 또는 LLM 완료 후 전송 전에 반영됩니다.

3. Auto 모드

개요

Auto 모드는 번들(Bundle) 단위로 URL 분석·웹 검색·LLM 요약을 자동 실행하고, 선택적으로 카카오톡·텔레그램으로 결과를 전송하는 자동화 기능입니다.

목적

  • 정기적으로 URL·웹 검색 기반 리서치를 자동화
  • 분석 결과를 메신저로 배포
  • 여러 번들을 독립적으로 관리·스케줄

주요 구성요소

구성요소역할관련 경로
AutoLayout번들 목록, 카카오 연동 UIsrc/lib/components/auto/AutoLayout.svelte
BundleEditor번들 폼, Run Now, 스케줄src/lib/components/auto/BundleEditor.svelte
autoStore번들 CRUD, 실행·스케줄src/lib/stores/auto.svelte.ts
scheduler스케줄 엔진, executeBundlesrc/lib/server/scheduler.ts

동작 흐름

flowchart TD
    A[번들 생성/편집] --> B{실행 방식}
    B -->|Run Now| C[POST /api/auto/execute]
    B -->|Start Schedule| D[POST /api/auto/schedule start]
    C --> E[executeBundle]
    D --> F[서버 setInterval / 60s tick]
    F --> E
    E --> G[URL fetch]
    G --> H{enableWebSearch?}
    H -->|yes| I[searchWeb + 상위 3 URL fetch]
    H -->|no| J[검증]
    I --> J
    J --> K[LLM 분석]
    K --> L[카카오 전송]
    L --> M[텔레그램 전송]
    M --> N[결과 반환 + IndexedDB 저장]

4. Chat API

개요

Chat 모드의 서버 API는 POST /api/chat 단일 엔드포인트로 SSE 스트리밍 응답을 반환합니다.

목적

  • 클라이언트와 LLM 사이의 스트리밍 중계
  • 웹 검색·페이지 수집 결과를 SSE 이벤트로 전달
  • 진행 단계(progress)를 실시간 UI에 반영

GET /api/llm/healthLLM 제공자 연결 확인src/routes/api/llm/health/+server.ts

5. Chat 모드

개요

Chat 모드는 JukimBot 앱의 기본 대화 화면으로, 로컬 Ollama 또는 OmniRoute(OpenRouter) LLM과 스트리밍 채팅을 제공합니다. 선택적으로 웹 검색을 켜면 검색 결과와 페이지 본문을 수집한 뒤 LLM이 근거 기반 답변을 생성합니다.

목적

  • 로컬·클라우드 LLM을 전환하며 대화형 질의응답 제공
  • 웹 검색·페이지 스크래핑으로 최신 정보 기반 답변 지원
  • 대화 이력을 브라우저 IndexedDB에 저장해 세션 간 유지
